# 開発・公開ガイド

## 1. 本番と開発環境を区別する

| 場所 | 役割 | 入力データ |
| --- | --- | --- |
| 現在のSites公開URL | 二人が実際に企画を入力する場所 | 本番D1に保存 |
| GitHub | コードと変更履歴を共同管理 | ユーザー入力データは含まれない |
| Claude Code / PCの開発環境 | コードを変更して試す場所 | その環境のローカルD1に保存 |

GitHubのソースコピーだけでSitesのアクセス権や本番DBを移設できるわけではありません。別ホスティングへ移す場合は、認証・アクセス制御、DBの書き出しと移行、秘密情報、公開手順を別途設計してください。

## 2. ローカル起動

Node.js >=22.13.0を使用してください。pnpmのバージョンはpackage.jsonのpackageManagerに合わせます。

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm build
```

初回、生成されたdist/server/wrangler.jsonを使ってローカルDBを作成します。

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_nervous_whizzer.sql
pnpm dev
```

起動時に表示されるローカルURLを開きます。同じローカルDBへ適用済みのSQLは再実行しません。DBマイグレーションが追加された場合は未適用のものを順番に適用します。

新規クローンはportableプロファイルで動きます。ChatGPT管理環境のsites-preview用設定はGitHubへコピーしていません。portableでのサインイン模擬動作はローカル専用であり、本番のアクセス権ではありません。

## 3. 変更前後の検証

```sh
pnpm exec tsc --noEmit
pnpm build
```

画面や保存処理を変更した場合は、該当する操作を実際に確認します。

- アイデアを追加・編集し、再読込して残る
- 全体図で同じカテゴリーの親子アイデアが表示され、循環する接続を選べない
- 統合時に元の案をアーカイブとして残し、復元できる
- 別セッションと更新が重なった場合に409で通知し、既存データを上書きしない
- 企画書を保存・書き出しできる
- スマートフォン幅で操作できる

現状のAPIはワークスペース全体をJSONで保存します。新しい項目を追加する際は、古い保存済みデータにその項目がなくても画面が動くようにしてください。

## 4. 二人で編集する手順

- オーナーが友人をGitHubリポジトリに招待し、友人が承諾する。
- 二人がそれぞれのClaude Codeからこのリポジトリを選ぶ。Claude側のGitHub連携で、この非公開リポジトリへのアクセスを許可する。
- 一つの変更につき一つのブランチで作業し、PRを作成する。
- 相手の変更を確認してからmainへ統合する。同じファイルの競合は解決してから統合する。

GitHubの共同編集者権限と、Sitesの外部利用者権限は別です。GitHubに招待しても、友人にSitesの公開権限が自動付与されるわけではありません。

## 5. 今の公開サイトに反映する

現在、自動同期は設定されていません。オーナーがSitesを使えるChatGPTから、リポジトリ名と反映するコミットSHAを指定して反映を依頼します。

反映担当は以下を行います。

1. GitHubの対象コミットと、現在のSitesソースを両方取得する。
2. それぞれの変更を比較し、GitHubにないSites側の更新を消さないように取り込む。
3. 元の `.openai/hosting.json` の project_id、D1バインディング、現在の共有設定を保持する。
4. DB変更がある場合は、既存データを保持する追加マイグレーションを確認する。
5. 型チェック・ビルド・必要な操作確認を行う。
6. Sitesの正規ワークフローでソースを同期し、そのコミットの成果物を保存・公開する。
7. 公開成功とURLを確認する。反映した変更と対応するGitHubコミットを記録する。

この手順は公開担当への引き継ぎです。GitHub ActionsからSitesへ公開する非公式APIや、オーナーのトークンを埋め込む仕組みは用意していません。

## 6. 将来Claude APIをアプリに組み込む場合

Claude Codeでの開発とは別の機能です。利用目的、送信するデータ、API認証、利用料金・上限、応答の検証、保存前の確認を設計してから実装します。現時点の類似判定はキーワード方式です。
